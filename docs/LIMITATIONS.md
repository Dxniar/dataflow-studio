# Known limitations

- Entire input files and before/after copies are held in memory. A 100-row preview limits rendering work, not RAM use. Configurable guards default to 50 MiB source size, 64 MiB table memory, 500,000 rows and 2,000,000 cells. They are safety limits rather than performance guarantees. There is no streaming engine.
- XLSX is treated as tabular data. Styles, merged cells, charts, macros, data validation, multiple-sheet workbook structure and original formulas are not preserved in exports. The selected worksheet becomes one output table.
- Formulas are never evaluated. Read values may depend on the last cached result saved by a spreadsheet program. Formula-like strings in exports are protected as text; CSV escaping adds a leading apostrophe and therefore intentionally changes those text values.
- CSV has no inherent schema. Default inference can lose leading zeros; explicit import types preserve stored text identifiers when selected before loading. Import schema, date formats and decimal/thousands separators are opt-in. Excel numeric display formatting cannot reconstruct textual IDs.
- Only `.csv` and `.xlsx` are supported. `.xls`, `.xlsm`, password-protected workbooks and remote URLs are outside scope.
- Headers must be nonempty and unique. Normalization or renaming that would produce collisions is rejected rather than silently merging columns.
- Filters are literal conditions combined with AND. There is no SQL/query language, expression evaluation, fuzzy matching, or relational JOIN. Merge appends rows using strict, union, or intersection schemas.
- Standardization is an exact value mapping. It does not guess whether similarly spelled values refer to the same business entity.
- Batch is sequential and reports per-file failures. Successful outputs remain when another file fails or the user cancels. Cancellation checks occur at safe boundaries, so a single pandas operation may complete first. Retry uses saved options and current failed/pending sources; successful checkpointed inputs are not reread.
- Output publication and SQLite checkpoints are separate transactions. After a hard process stop, an existing output may be ambiguous. Interrupted recovery uses collision-error policy in a new saved job and stops for review instead of creating duplicate numbered outputs. This is not an exactly-once transaction across the filesystem and database.
- An output directory on a local filesystem is recommended. Cloud sync, network filesystem behavior and external programs racing to modify files are outside the validated environment.
- The GUI supports a single active job. Settings, workflow/rules, recent paths, history and job metadata persist in `%LOCALAPPDATA%/DataFlowStudio/workspace.sqlite3`; tables are not stored or automatically reopened. Configuration and filenames can still be sensitive; storage is a normal local file. A rotating metadata log remains under `%LOCALAPPDATA%/DataFlowStudio/logs/dataflow.log` (1 MB plus two backups); table cells are excluded.
- The Windows distribution is a portable folder, not an installer or signed executable. Keep its `_internal` folder beside the EXE. OS trust prompts can occur for unsigned builds.
- This is an AI-assisted personal portfolio demo with synthetic data, not evidence of a paid client engagement or independent certification.
